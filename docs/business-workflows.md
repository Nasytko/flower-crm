# Business workflows (кратко)

Внутренний ERP цветочного магазина. Платежи, CRM-воронка и публичный API сайта **не** входят в текущий контур.

## Склад и остатки

- **FLOWER** имеют `ProductStock` (on hand / reserved / available) и партии `StockLot`.
- **SERVICE** без складского остатка.
- Списание вручную идёт из **доступного** остатка (нельзя трогать резерв).
- Движения `StockMovement` неизменяемы; себестоимость цветов — FIFO по партиям.

## Поставки

- Черновик → проведение создаёт лоты и увеличивает on hand.
- Во время **активной инвентаризации** склад заморожен: проведение поставок/списаний/завершение заказов блокируется.
- Коррекция отменяет исходную поставку и создаёт новую.

## Резервы и заказы

- Создание/правка заказа в статусе NEW пересчитывает резервы по приоритету (дата/время).
- Shortage не блокирует создание заказа, но блокирует READY/COMPLETED (`ORDER_HAS_SHORTAGE`).
- Отмена заказа освобождает резерв и **перераспределяет** остаток другим заказам.
- COMPLETED атомарно: SALE + FIFO COGS + снятие резерва; ошибка посередине откатывает транзакцию.

## Инвентаризация

- Снимок → подсчёт → complete.
- Факт **не ниже** reserved.
- Излишек создаёт uncosted inventory-лот; недостача списывает FIFO.

## Букеты

- Рецепт (состав), не отдельный остаток. В заказе разворачиваются в компоненты для резерва/COGS.
